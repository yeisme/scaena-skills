# 万相3.0 视频提示词优化

把粗略分镜/故事概要，改写成万相3.0 可直接提交的专业提示词。方法论底层是扩散模型的条件注入机制，所有写法收敛到 Wan3.0 的单一入口、@图片N 指代口径与实测参数边界。本技能只服务 wan3.0-video / wan3.0-video-prime，只管"怎么写 prompt"；下载后的验收/测 RMS/帧对比归 wan3-generation-verification，不在本技能内。 注意：wan3.0-video 与 wan3.0-video-prime 是同一个模型，仅生成速度不同，模型能力与写法规则完全一致——全文任何规则、实测行为、模板都不区分 Prime，勿把某条写法或现象标注为"Prime 专用/固有"。

仓库集成口径：本仓库未安装名为 wan3.0-video-generation / wan3-generation-verification 的独立 skill；本技能引用的这两处边界分别对应 Scaena 生成提交层（`scaena video generate`、`createVideoProviderTask`，路由见 `$scaena-production-operator`）与 Scaena 验收/校验流程（`scaena video task prompt --verify-prompt-file`、下载验收与 ASR 复核）。本技能只产出 prompt 正文，不代替提交与验收。

全文以末尾《出片前自检清单》为主纲。正文先建模型认知，再给三张贯穿全程的写法规则卡（否定卡 / 声音卡 / 器物卡），后文一律引用卡片、不再复述。三卡是"降低概率风险"的管理工具，不是判通过/不通过的红线——真正的裁判是出片，评审时先想调度（见《调度优先于合规》），再对着卡做取舍。

## 使用前提

Wan3.0 只有一个模型入口，生成形态由 input.media[].type 决定。优化前必须先确定形态（对应要上传哪些 media），否则 prompt 的详略、指代、互斥都会写错。

判定流程：

```text
用户上传了什么 / 要什么效果？
├─ 只有文本                                  → T2V 文生（无 media）
├─ 一张首帧图 + "让它动起来"                  → I2V 首帧（first_frame ×1）
├─ 首帧 + 尾帧两张图，要 A→B 过渡             → 首尾帧（first_frame + last_frame）
├─ 角色/场景参考图（设计稿/四视图/概念图）+叙事 → 全能参考（reference_image）
├─ 要借一段视频的运镜/动作/特效               → 全能参考（reference_video）
├─ 要给某角色锁音色                           → 全能参考（reference_audio 或 reference_voice）
└─ 有原视频 + 改风格/换元素/延长              → 视频编辑·延长（reference_video）
```

形态不确定时默认按 T2V 优化，并在开头注明"按 wan3.0 文生形态优化，如有首帧/参考素材请说明以切换形态并调整写法"。

## 核心方法论

机制表与写作原则：`references/methodology.md`。三条铁律：一镜一动作 / 不矛盾 / 删冗余。

## 优化边界（不可越权）

- 不自行添加台词：用户输入无台词时，在全局音频或基调中声明「全片无台词」，并在每个镜头的台词栏统一写「无」；这是合法叙事选择，不许补词。
- 用户台词逐字保留：提供的台词/对白/旁白原样保留（含标点、语气词、重复），禁止删减、缩写、润色、合并。台词超长时调时长适配（见时长专章），确需动台词必须先征得同意。
- 不改情绪走向 / 角色关系 / 叙事节奏。
- 格式留白不硬填：无台词镜的台词栏写「无」，但声音设计不能留白，必须给出环境声或动作声，见〖声音卡〗。

## 三张写法规则卡（贯穿全程引用，勿在后文复述）

### 〖否定卡〗 —— 正向排除（negative_prompt 已废弃）

Wan3.0 不再支持 negative_prompt。"不要X"与"X"在编码器里指向同一区域，写了反而加强；唯一有效的排除是删掉那个词、换成目标状态描述。

| 否定写法（禁用） | 正向排除写法 |
| --- | --- |
| 不要出现文字/字幕 | 画面干净无叠加图形，纯实拍质感 |
| 不要变形 | 五官与肢体比例保持稳定自然，轮廓边缘清晰 |
| 镜头不要动 | 固定镜头，机位与焦距全程不变 |
| 不要人声 | 全片无台词，仅保留环境音 |
| 不要多余的手 | 双手始终在画面内且可数，动作简洁 |
| 背景不要乱 | 背景为单一浅灰无缝墙面，虚化处理 |
| 严禁BGM | 无背景音乐，仅环境音效与动作音效 |

原生对白任务的全局设定只保留一句正向画面纯净描述：「全片画幅保持干净，画面上缘、中部与下缘均为连续场景延伸」。不在各镜重复相关约束。该描述用于降低烧字概率，但不能保证完全消除模型原生烧字。

推论：禁用词表不进 prompt。年代/奇幻类要清零现代器物词（水杯、玻璃、手机…），直接换成形制名，而不是写"不要玻璃杯"（详见〖器物卡〗与设定合规层）。

### 〖声音卡〗 —— 静默镜 ≠ 静音

三种状态要分清：台词（逐字，口型对齐）/ 环境声（任何写实空间都必须有、且连续）/ 刻意静音（主观失聪、掐断式收尾等，仅这类才写"静音"并说明是"刻意的静音处理"）。

写"环境近乎静音/环境音极低/死寂"这类词，模型有时会照字面输出接近数字静音（观感是"人一不说话就没声音"，比串音更突兀），反复写"无对白"也会加强这一倾向。注意这是概率性风险、非必然——实测有反例（"殿内死寂底噪"一句照样出了连续环境声，无 −inf 段），所以它是"别去赌、优先正面写实声源"的提示，不是判某条 prompt 必崩的依据。

正确写法是把底噪正面写实并连续：「保留清晰的室内底噪：烛芯噼啪、夜风轻拂帘幔、衣料摩擦与呼吸声，音量低但连续不断」；静默镜的处理靠台词栏写「无」两字 + 本镜点 1–2 个具体声源，不写"禁止出声/不许说话"这类否定句；有动作的镜把音效写实（脚步由近及远、瓷盏轻磕、裙裾扫过地面）。

例外：画外音/接电话——说话者入画但声音来自画外时，才需要显式声明"嘴唇闭合、口型不动"，防止模型给他配口型。这是唯一保留"嘴唇闭合"字样的场景，静默镜本身不需要。

无台词单元要逐镜点名声源：全局写一句"底噪连续"只对有台词的单元有效，对整段近乎无台词的短单元无效，后者必须逐镜列 1–2 个具体声源；实在不可控时在拼接阶段铺环境音床（成本最低）。

正向利用联合生成：声源事件能牵引画面——关门"砰"带动人物肩部一沉、远处雷鸣压暗色调。写关键动作时顺手点一声可生成的声源，节奏更贴。

（验收阈值属 wan3-generation-verification，本技能不列数字。）

### 〖器物卡〗 —— 反射会实体化、相邻客体会合体

cross-attention 没有"这是两件器物"的概念，只看共现。头号铁律：连"合规声明"本身都不能出现被排除物的名词。 写"盏内绝不燃烧、不得出现火焰火苗灯芯"＝把"火焰/火苗/灯芯"喂进条件，反而召唤它（扩散模型不吃负向，见〖否定卡〗）。只描述目标状态、以及"某物只在哪里存在"。

边界（风险提示，非判死刑）：参考图与场景氛围提供的视觉先验层，权重高于文字层。当"碗状敞口容器+夜戏+画面唯一暖光源+场景图本就画碗形发光物"这类原型条件同时被激活时，文字压不住的先验风险最高——但这同样是概率性风险、非必然。实测反例：一句"宫灯暖黄主光 + 双手端着青瓷水杯"照样渲染出了干净的青瓷饮器，全程没有变成碗形灯（明火只落在落地铜烛台上）。所以本卡的用法是：当多条件叠满时优先改素材/形制（换参考图、换器物形制、加首帧约束），别去赌；而不是"看到杯/盏+夜戏就判这条 prompt 必崩、要求返工"。真正评估以出片为准。同理：角色参考图画长发你说"短发"通常没用、场景参考是赛博朋克你写"宋代宫廷"多半白搭——这些都是"高概率打不赢、优先改来源"的提示。

- 火只写在它该在的地方，绝不写它不在哪：与其"盏内不得有火"，不如「青瓷盏盛着清澈茶汤，盏口只映一点暖色高光」+「带立柱底座的铜烛台是画面里唯一的明火，火苗只在它的灯芯上跳动」。火焰/火苗这些词只出现在烛台那一句，与盏分处不同句、绝不相邻。
- 反射只写受光与高光，不写被反射物：写"茶面映出烛焰""镜中映出人影"，模型常把被反射物画进表面。改「茶面平静，只浮着一点暖色高光」。
- 易合体对分句写、各自独立成句：容器×火源、镜面×人影、水面×倒影，同句共现＝给模型出融合题。分两句各写各的，别用"不得合体"这种否定缝合（那仍是把两者放进同一语义窗口）。
- 视觉先验击穿文字时改形制/画面来源，而不是堆否定词：若场景参考图本身画满碗状/杯状发光灯，再强的文字声明也压不过（实测复现）。解法是换非碗形盛器（带盖盏、执壶、托盒）、给内容物注入动态（清水晃动反证非灯）、或把场景光源改写成落地立柱烛台——从形制与画面来源切断。
- 动作句受词锁定同一器物：「低头朝茶汤吹一口气」而非跨器物。
- 名词有默认渲染值：泛词（杯子/桌子/手机）覆盖语义最大，几乎必落到现代众数；形制名（带茶托的敞口青瓷碗）把条件压进小流形。写细是为收窄可选集，不是为描述更美。

## Wan3.0 协议硬约束（写作前必查）

口径以平台当前返回为准，参数随版本可能调整。

### 参考素材指代 —— 用 @图片N，不用 图N

- 图片写 @图片1、@图片2…；视频 @视频1…；音频 @音频1…——带 @、全称"图片/视频/音频"。
- 序号 = 该类型内上传顺序，图片 / 视频 / 音频分开计数（可同时有 @图片1 和 @视频1）。
- 同一对象可在不同位置多次 @，用来精准控制参考意图，也是提高遵循度的推荐手段。
- 旧版不带 @ 的「图1/视频1」会拉低命中率；改写历史 prompt 时优先替换成 @ 形式。
- 挂图数量与风格一致性见〖核心方法论〗"参考图归一化"行：reference_image ≤10 但经验 >4 张引导力递减，多张色温/光影方向需统一。

### 正向排除

见〖否定卡〗，此处不重复。

### 只影响"正文怎么写"的两条

- 横竖屏不靠文字：ratio 是提交参数，prompt 里写"竖屏/9:16"模型不吃，别浪费 token——横竖屏交提交层，正文只专注画面内容。
- reference_* 与 first_frame/last_frame 互斥：一个单元只能走一条路径，这决定你按"视觉先验"还是"帧锚点"做减法（见《空间锚定与镜头写法》）；last_frame 必须配 first_frame。

提交与出片参数不归本技能：resolution/ratio/duration/audio/seed/watermark 的取值、素材大小规格、是否关闭智能改写等，都属生成层，交由 wan3.0-video-generation 处理。本技能只产出 prompt 正文。唯一例外：duration 的 30s 上限会反过来决定叙事要不要拆成多个生成单元，因此作为写作规划保留在《时长、拆分与语速校准》。

时长、拆分、语速与发音：`references/duration.md`。

## 交付方式

本技能默认只产出 prompt 正文，不自动出片。 仅当用户明确说"跑一下/出 case/生成看看/批量跑"才进入出片环节——但出片参数（duration/resolution/ratio/audio 等）的确认、CLI 提交、以及生成后的验收，都不属本技能，交由 wan3.0-video-generation / wan3-generation-verification 处理。

"优化提示词重跑"的默认语义是：使用优化后的完整 prompt，保持单条原生音视频生成。 不得擅自改成多段生成、剪辑拼接、后期加速或独立配音；如确需改变方案，必须先说明原因并获得用户明确同意。重跑时除用户指定修正项外，尽量冻结台词、镜头、动作、参考素材映射和时长，便于判断该修正是否真正有效。

写镜头前的〖设定档案〗：`references/setting-archive.md`。

空间锚定、动作具象化、转场：`references/staging.md`。

输出格式与类型适配：`references/output-format.md`。

## 调度优先于合规（评审以出片为准）

三张卡和自检清单是降低概率风险的工具，不是判通过/不通过的红线。先想调度，再对着卡做取舍；先出片、看片，不要因命中"高危条件"就断言必崩。连续 2–3 次同类抽卡失败才谈改方案，不得静默换成分段/后期/独立配音。

导演级调度示例与重试归因：`references/directing-priority.md`。

出片前自检清单：`references/preflight-checklist.md`。写完对照该清单。

## If this fails

| Trigger | First fix | Still failing |
| --- | --- | --- |
| 否定句 /「不要X」进 prompt | 换成目标状态；被排除物名词也不出现 | 见〖否定卡〗 |
| 静默镜数字静音 | 台词栏写「无」+ 点名 1–2 个声源 | 不写「嘴唇闭合」除非画外音 |
| 茶盏长明火 / 器物合体 | 改形制或参考图，不堆否定 | 见〖器物卡〗；先验打不赢文字 |
| 台词被改写 | 逐字保留；超长调 duration | 拆单元须用户同意 |
| 把抽卡波动当写法失败 | 保持完整 prompt 再抽 | 连续 2–3 次同类失败才谈改方案 |
| 擅自分段/后期/独立配音 | 停；默认单条原生重跑 | 必须用户明确授权 |
| 把提交参数写进 prompt | 正文从【全局设定】起 | resolution/ratio 归生成层 |
