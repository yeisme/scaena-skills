# 万相3.0 视频提示词优化

把粗略分镜/故事概要，改写成万相3.0 可直接提交的专业提示词。方法论底层是扩散模型的条件注入机制，所有写法收敛到 Wan3.0 的单一入口、@图片N 指代口径与实测参数边界。本技能只服务 wan3.0-video / wan3.0-video-prime，只管"怎么写 prompt"；下载后的验收/测 RMS/帧对比归 wan3-generation-verification，不在本技能内。 注意：wan3.0-video 与 wan3.0-video-prime 是同一个模型，仅生成速度不同，模型能力与写法规则完全一致——全文任何规则、实测行为、模板都不区分 Prime，勿把某条写法或现象标注为"Prime 专用/固有"。

仓库集成口径：本仓库未安装名为 wan3.0-video-generation / wan3-generation-verification 的独立 skill；本技能引用的这两处边界分别对应 Scaena 生成提交层（`scaena video generate`、`createVideoProviderTask`，路由见 `$scaena-production-operator`）与 Scaena 验收/校验流程（`scaena video task prompt --verify-prompt-file`、下载验收与 ASR 复核）。本技能只产出 prompt 正文，不代替提交与验收。

全文以末尾《出片前自检清单》为主纲。正文先建模型认知，再给三张贯穿全程的写法规则卡（否定卡 / 声音卡 / 器物卡），后文一律引用卡片、不再复述。三卡是"降低概率风险"的管理工具，不是判通过/不通过的红线——真正的裁判是出片，评审时先想调度（见《调度优先于合规》），再对着卡做取舍。

## 使用前提

Wan3.0 只有一个模型入口，生成形态由 input.media[].type 决定。优化前必须先确定形态（对应要上传哪些 media），否则 prompt 的详略、指代、互斥都会写错。

判定流程：

```text
用户上传了什么 / 要什么效果？
├─ 只有文本                                  → T2V 文生（无 media）
├─ 一张首帧图 + "让它动起来"                  → I2V 首帧（first_frame ×1）
├─ 首帧 + 尾帧两张图，要 A→B 过渡             → 首尾帧（first_frame + last_frame）
├─ 角色/场景参考图（设计稿/四视图/概念图）+叙事 → 全能参考（reference_image）
├─ 要借一段视频的运镜/动作/特效               → 全能参考（reference_video）
├─ 要给某角色锁音色                           → 全能参考（reference_audio 或 reference_voice）
└─ 有原视频 + 改风格/换元素/延长              → 视频编辑·延长（reference_video）
```

形态不确定时默认按 T2V 优化，并在开头注明"按 wan3.0 文生形态优化，如有首帧/参考素材请说明以切换形态并调整写法"。

## 核心方法论

视频生成是扩散模型：从噪声迭代去噪，文本编码器的语义向量是去噪条件。Wan3.0 支持音视频联合生成与多分镜生成——prompt 里的台词/声音描述既驱动音频，又通过跨模态注意力反哺画面；时间标注是模型可解析的时序条件。

机制 → 写作原则

| 模型机制 | 对 prompt 的影响 | 写作原则 |
| --- | --- | --- |
| 注意力按 token 分配，冗余词摊薄核心条件权重（≠5000 字符硬上限，后者见协议章） | 词越多，每个词的引导力越稀 | 精简优先：删到一个词都不承载新信息为止 |
| 无独立 guidance 参数可调（Wan3.0 未开放 CFG/scale） | 遵循度只能靠文字本身控 | 调遵循度＝删泛词 + 加具体锚点 + 加一致性声明，不是加感叹号 |
| 时空注意力建模帧间变化 | 无时间指令 → 静止或乱漂 | 动作+运镜是核心输入 |
| 去噪步数有限 | 多阶段动作无法精确分配 | 一镜一动作，复杂序列拆镜 |
| 空间构图文本编码不稳定 | 绝对坐标靠不住 | 景别优先，多人同框才用画左/画右辅助；首帧/参考图已锁定时不重复 |
| "不要X"与"X"语义指向同一区域 | 否定式反而召唤X | 禁止否定句，见〖否定卡〗 |
| 光影/风格词是全局色调先验 | 一句锚定整体调性 | 光影和风格是高杠杆信号 |
| 参考图在 cross-attention 里按数量归一化 | 挂图越多，每张引导力越被摊薄、风格先验互相冲突 | 挂图克制（经验 >4 张明显递减），只挂承载关键信息的图，多张色温/光影方向要一致 |
| 音频与画面联合生成、互为条件 | 声音描述能牵引画面节奏 | 用声源事件驱动动作/节奏（门砰→人物一惊），不只写"避免静音" |
| 实测主体/核心动作前置命中更稳（内容驱动、非严格位置优先） | 开头注意力预算最足 | 主体+核心动作放最前，风格氛围靠后 |
| 潜空间无物理单位 | "约2米""30cm"权重极低 | 相对量级优于精确数值（例外：时间标注必须保留） |
| 无世界模型，未指定区域由训练先验的众数填补 | 你没写的部分不会"按设定补全"，只会按语料平均水平补 | 先建设定档案再写镜头：把每处空隙用具体目标状态占回来（见设定合规层） |

三条铁律：一镜一动作 / 不矛盾 / 删冗余。

## 优化边界（不可越权）

- 不自行添加台词：用户输入无台词时，在全局音频或基调中声明「全片无台词」，并在每个镜头的台词栏统一写「无」；这是合法叙事选择，不许补词。
- 用户台词逐字保留：提供的台词/对白/旁白原样保留（含标点、语气词、重复），禁止删减、缩写、润色、合并。台词超长时调时长适配（见时长专章），确需动台词必须先征得同意。
- 不改情绪走向 / 角色关系 / 叙事节奏。
- 格式留白不硬填：无台词镜的台词栏写「无」，但声音设计不能留白，必须给出环境声或动作声，见〖声音卡〗。

## 三张写法规则卡（贯穿全程引用，勿在后文复述）

### 〖否定卡〗 —— 正向排除（negative_prompt 已废弃）

Wan3.0 不再支持 negative_prompt。"不要X"与"X"在编码器里指向同一区域，写了反而加强；唯一有效的排除是删掉那个词、换成目标状态描述。

| 否定写法（禁用） | 正向排除写法 |
| --- | --- |
| 不要出现文字/字幕 | 画面干净无叠加图形，纯实拍质感 |
| 不要变形 | 五官与肢体比例保持稳定自然，轮廓边缘清晰 |
| 镜头不要动 | 固定镜头，机位与焦距全程不变 |
| 不要人声 | 全片无台词，仅保留环境音 |
| 不要多余的手 | 双手始终在画面内且可数，动作简洁 |
| 背景不要乱 | 背景为单一浅灰无缝墙面，虚化处理 |
| 严禁BGM | 无背景音乐，仅环境音效与动作音效 |

原生对白任务的全局设定只保留一句正向画面纯净描述：「全片画幅保持干净，画面上缘、中部与下缘均为连续场景延伸」。不在各镜重复相关约束。该描述用于降低烧字概率，但不能保证完全消除模型原生烧字。

推论：禁用词表不进 prompt。年代/奇幻类要清零现代器物词（水杯、玻璃、手机…），直接换成形制名，而不是写"不要玻璃杯"（详见〖器物卡〗与设定合规层）。

### 〖声音卡〗 —— 静默镜 ≠ 静音

三种状态要分清：台词（逐字，口型对齐）/ 环境声（任何写实空间都必须有、且连续）/ 刻意静音（主观失聪、掐断式收尾等，仅这类才写"静音"并说明是"刻意的静音处理"）。

写"环境近乎静音/环境音极低/死寂"这类词，模型有时会照字面输出接近数字静音（观感是"人一不说话就没声音"，比串音更突兀），反复写"无对白"也会加强这一倾向。注意这是概率性风险、非必然——实测有反例（"殿内死寂底噪"一句照样出了连续环境声，无 −inf 段），所以它是"别去赌、优先正面写实声源"的提示，不是判某条 prompt 必崩的依据。

正确写法是把底噪正面写实并连续：「保留清晰的室内底噪：烛芯噼啪、夜风轻拂帘幔、衣料摩擦与呼吸声，音量低但连续不断」；静默镜的处理靠台词栏写「无」两字 + 本镜点 1–2 个具体声源，不写"禁止出声/不许说话"这类否定句；有动作的镜把音效写实（脚步由近及远、瓷盏轻磕、裙裾扫过地面）。

例外：画外音/接电话——说话者入画但声音来自画外时，才需要显式声明"嘴唇闭合、口型不动"，防止模型给他配口型。这是唯一保留"嘴唇闭合"字样的场景，静默镜本身不需要。

无台词单元要逐镜点名声源：全局写一句"底噪连续"只对有台词的单元有效，对整段近乎无台词的短单元无效，后者必须逐镜列 1–2 个具体声源；实在不可控时在拼接阶段铺环境音床（成本最低）。

正向利用联合生成：声源事件能牵引画面——关门"砰"带动人物肩部一沉、远处雷鸣压暗色调。写关键动作时顺手点一声可生成的声源，节奏更贴。

（验收阈值属 wan3-generation-verification，本技能不列数字。）

### 〖器物卡〗 —— 反射会实体化、相邻客体会合体

cross-attention 没有"这是两件器物"的概念，只看共现。头号铁律：连"合规声明"本身都不能出现被排除物的名词。 写"盏内绝不燃烧、不得出现火焰火苗灯芯"＝把"火焰/火苗/灯芯"喂进条件，反而召唤它（扩散模型不吃负向，见〖否定卡〗）。只描述目标状态、以及"某物只在哪里存在"。

边界（风险提示，非判死刑）：参考图与场景氛围提供的视觉先验层，权重高于文字层。当"碗状敞口容器+夜戏+画面唯一暖光源+场景图本就画碗形发光物"这类原型条件同时被激活时，文字压不住的先验风险最高——但这同样是概率性风险、非必然。实测反例：一句"宫灯暖黄主光 + 双手端着青瓷水杯"照样渲染出了干净的青瓷饮器，全程没有变成碗形灯（明火只落在落地铜烛台上）。所以本卡的用法是：当多条件叠满时优先改素材/形制（换参考图、换器物形制、加首帧约束），别去赌；而不是"看到杯/盏+夜戏就判这条 prompt 必崩、要求返工"。真正评估以出片为准。同理：角色参考图画长发你说"短发"通常没用、场景参考是赛博朋克你写"宋代宫廷"多半白搭——这些都是"高概率打不赢、优先改来源"的提示。

- 火只写在它该在的地方，绝不写它不在哪：与其"盏内不得有火"，不如「青瓷盏盛着清澈茶汤，盏口只映一点暖色高光」+「带立柱底座的铜烛台是画面里唯一的明火，火苗只在它的灯芯上跳动」。火焰/火苗这些词只出现在烛台那一句，与盏分处不同句、绝不相邻。
- 反射只写受光与高光，不写被反射物：写"茶面映出烛焰""镜中映出人影"，模型常把被反射物画进表面。改「茶面平静，只浮着一点暖色高光」。
- 易合体对分句写、各自独立成句：容器×火源、镜面×人影、水面×倒影，同句共现＝给模型出融合题。分两句各写各的，别用"不得合体"这种否定缝合（那仍是把两者放进同一语义窗口）。
- 视觉先验击穿文字时改形制/画面来源，而不是堆否定词：若场景参考图本身画满碗状/杯状发光灯，再强的文字声明也压不过（实测复现）。解法是换非碗形盛器（带盖盏、执壶、托盒）、给内容物注入动态（清水晃动反证非灯）、或把场景光源改写成落地立柱烛台——从形制与画面来源切断。
- 动作句受词锁定同一器物：「低头朝茶汤吹一口气」而非跨器物。
- 名词有默认渲染值：泛词（杯子/桌子/手机）覆盖语义最大，几乎必落到现代众数；形制名（带茶托的敞口青瓷碗）把条件压进小流形。写细是为收窄可选集，不是为描述更美。

## Wan3.0 协议硬约束（写作前必查）

口径以平台当前返回为准，参数随版本可能调整。

### 参考素材指代 —— 用 @图片N，不用 图N

- 图片写 @图片1、@图片2…；视频 @视频1…；音频 @音频1…——带 @、全称"图片/视频/音频"。
- 序号 = 该类型内上传顺序，图片 / 视频 / 音频分开计数（可同时有 @图片1 和 @视频1）。
- 同一对象可在不同位置多次 @，用来精准控制参考意图，也是提高遵循度的推荐手段。
- 旧版不带 @ 的「图1/视频1」会拉低命中率；改写历史 prompt 时优先替换成 @ 形式。
- 挂图数量与风格一致性见〖核心方法论〗"参考图归一化"行：reference_image ≤10 但经验 >4 张引导力递减，多张色温/光影方向需统一。

### 正向排除

见〖否定卡〗，此处不重复。

### 只影响"正文怎么写"的两条

- 横竖屏不靠文字：ratio 是提交参数，prompt 里写"竖屏/9:16"模型不吃，别浪费 token——横竖屏交提交层，正文只专注画面内容。
- reference_* 与 first_frame/last_frame 互斥：一个单元只能走一条路径，这决定你按"视觉先验"还是"帧锚点"做减法（见《空间锚定与镜头写法》）；last_frame 必须配 first_frame。

提交与出片参数不归本技能：resolution/ratio/duration/audio/seed/watermark 的取值、素材大小规格、是否关闭智能改写等，都属生成层，交由 wan3.0-video-generation 处理。本技能只产出 prompt 正文。唯一例外：duration 的 30s 上限会反过来决定叙事要不要拆成多个生成单元，因此作为写作规划保留在《时长、拆分与语速校准》。

## 时长、拆分与语速校准

单次生成时长上限 30s。推荐 ≤10s 效果最佳，一致性通常随时长增加而衰减；但 15s、20s 仍是合法且可用的完整单条生成，不因超过 10s 就机械拆分。

### 生成单元决策

先按台词把"需求时长"算出来（需求时长 = ⌈台词字数 ÷ 4⌉ + 计划静默秒数），再按下表定策略——时长是台词的因变量，不要先拍时长再抠台词字数：

| 需求时长 | 策略 |
| --- | --- |
| ≤10s | 单次生成（多分镜一次出，衔接最紧、风格最稳） |
| 10–30s | 默认单次生成，直接把算出的时长写进 duration（≤30 全合法）；建议切镜≤6、无跨场景跳转、结尾声明跨镜一致性。关键动作尽量留足过程时间，1s 短镜仅用于简单反应或短句，不能把"每镜≥3s"当硬门槛 |
| 30–36s（仅超 ≤20%） | 可在不改台词的前提下压进 30s：先压缩静默镜，再提高目标语速；若用户明确要求保持完整时长或单条结构，遵从用户要求 |
| >36s | 默认建议按场景断点拆成多个 ≤30s 生成单元；执行拆分前说明原因，用户要求"完整提示词单条原生重跑"时不得擅自改成分段或后期方案 |

### 实测校准（wan3.0 逐字台词，写作规划用）

- 时间戳与台词截止都是软约束。 它们主要控制相对节拍、先后关系和密度，模型可能整体后移、合并相邻短镜，或把最后一句延伸到视频末尾。可以写「全部台词在 N 秒前结束」提高命中率，但不得宣称绝对秒点会被精确执行。
- 规划字速与实际字速分开。 舒适规划值通常约 4–4.5 个中文字/秒；紧凑对白可尝试约 5–5.4 字/秒，但越紧越容易吞音、弱化声调或挤占结尾收束。
- 全局目标必须与逐句窗口一致。 先逐句计算 该句中文字数 ÷ 该句发声窗口秒数，再计算 全部中文字数 ÷ 全部发声窗口总和；除两字短句、结巴和必要停顿外，各句应落在同一目标区间。若全局写 5.5–6.5 字/秒，而逐句合计只有 4.4 字/秒，提示词内部即自相矛盾。
- 总片长不能代替发声窗口。 语速核算只统计实际分配给对白的窗口，不把建立镜、动作镜和句间静默算入分母。用 需求时长 = ⌈台词字数 ÷ 4⌉ + 计划静默秒数 反推总时长，只是初始规划；之后仍须逐句复核。
- 不要把"提示词窗口缩短"写成"成片已经提速"。 原生音视频模型可能不服从窗口；生成后应交给验证环节，用 ASR 时间戳比较每句起止、累计发声时长和全部对白跨度。ASR 对同音词可能转写错误，专有词最终必须结合人耳复核。
- 短台词不必摊大总时长。 给足时间时，模型可能铺满预算，也可能说完后留出环境声；静默尾镜有助于收束，但同样不是确定保证。
- 段尾动作要显式收住：单元结尾不声明，模型常自行补"起身/走动"收势，与下一单元开头重复。最后一镜写清结束姿态、站位、视线和持续状态。
- 升分辨率不修内容问题：道具串味、镜序漂移、发音波动这类内容层失败，换更高分辨率通常仍会复现；应回到提示词约束、素材和模型能力边界判断。

### 长剧三类常见返工，怎么用设定话术压

这三点在 Good Case 里都不是靠"禁止句"解决的，而是把它写成正面的导演意图，放进【全局设定·其他/基调】和【场景与空间说明】：

- 跨镜空间错位 → 【场景与空间说明】逐人钉死方位（谁坐哪、朝向谁、间距），【全局设定·其他】写一句「机位变化时人物位置、朝向与彼此间距延续上一镜的结束状态，全片为同一间连续宫室」；对话片段在基调里点明「保持稳定正反打，机位在人物同侧」。
- 模型自增台词 → 不用"不许说话"这类否定句。静默镜的台词栏直接写「无」两字即可；如全片台词有明确边界，在【全局设定·基调】写「全片仅 X 句对白，集中在镜N–镜M，其余为纯画面与环境声」，把"哪几镜有台词"讲成正面事实。
- 声音跨镜串流 → 【全局设定·基调】写「每镜环境音起于本镜切镜点、随切镜自然更替」，比逐镜声明更省事，也符合 Good Case 只在必要处点声源的习惯。

另两条易踩：道具/器物问题先按〖器物卡〗判断是不是视觉先验冲突（是则改素材，不在文字上打磨）；四宫格/多视图场景图做 reference_image 时在【场景资产】加一句「@图片N 是同一空间的多视角参考，成片只呈现单一机位画面」，实测不会出分屏。

### 台词时长适配（超长时调时长，不改台词）

优先级：给该镜加时长（总预算内重分）→ 上调生成时长（≤30s）→ 台词跨镜分配（延续跨越切镜，影视常用）→ 仍超上限才拆单元（判据见上）→ 全用尽仍不可行才告知用户"台词超出可生成时长"、经同意后删改。英文缩写（PUA/CEO 等）建议换中文念法避免语音念错，替换前告知用户。

### 专有词与易错发音

Wan3.0 原生音视频不是确定性 TTS，同一提示词不同抽卡可能产生不同咬字、声调和连读结果。发音注记只提高命中率，不构成保证。

- 用户给出的台词文字保持原样；发音信息写在角色表演指导括号内，不改台词正文。
- 使用"汉字字源/语义锚点 + 拼音 + 声调"的组合，例如：「"祖制"两字清晰读作"祖先"的"祖"（zǔ，第三声）和"制度"的"制"（zhì，第四声）」。仅写拼音通常弱于同时给出字源。
- 全局先定义一次；每个实际出现位置再就地强化一次。提交前统计真实出现次数，避免写"四处"但正文实际有五处。
- 紧凑对白仍应给易错词留出清晰咬字空间。优先写「整体连贯，专有词逐字清晰，句末立即收束」，避免"字间极度紧凑"与"逐字清晰"互相冲突。
- 连续 2–3 次仍在同一词上失败时，归类为模型执行波动或能力边界；保持主体提示词稳定抽取候选，不继续无限叠加同义发音说明。是否改用独立配音、后期或其他能力，必须由用户明确授权。

### 单镜头时长经验

无台词镜 1–2s；短台词（≤10字）≥2s；中台词（10–30字）≥3–4s；长台词（≥30字）≥5–6s。计算公式：镜头时长 ≥ 台词字数÷4 + 表演停顿(1–2s)。

## 交付方式

本技能默认只产出 prompt 正文，不自动出片。 仅当用户明确说"跑一下/出 case/生成看看/批量跑"才进入出片环节——但出片参数（duration/resolution/ratio/audio 等）的确认、CLI 提交、以及生成后的验收，都不属本技能，交由 wan3.0-video-generation / wan3-generation-verification 处理。

"优化提示词重跑"的默认语义是：使用优化后的完整 prompt，保持单条原生音视频生成。 不得擅自改成多段生成、剪辑拼接、后期加速或独立配音；如确需改变方案，必须先说明原因并获得用户明确同意。重跑时除用户指定修正项外，尽量冻结台词、镜头、动作、参考素材映射和时长，便于判断该修正是否真正有效。

## 设定合规层（写镜头前必建〖设定档案〗）

先区分提示词缺口与模型执行波动。现代玻璃水杯、茶盏里长明火、夜间卸妆还戴凤冠、静默段没环境声，常由设定未钉牢或视觉先验冲突引起；同一完整提示词不同抽卡偶发发音、动作或镜序偏差，则可能属于模型执行波动。前者应修提示词或素材，后者应保持控制变量抽取候选，不能把所有失败都归咎于写法。

扩散模型没有稳定的"设定补全"能力，未写明的部分容易落回训练先验。因此写镜头前要把每一处关键空隙用具体目标状态预先占回来——能被写进条件的才存在，剩下的更容易归于先验（机制见〖否定卡〗推论、〖器物卡〗、〖声音卡〗，此处不重述）。

写第一镜前先产出〖设定档案〗（全片段共享，多单元复用同一份）：

- 世界四要素：时代与地域、场合（礼仪状态，如"夜·寝殿卸妆"）、时段与光源清单（烛台/灯/月光，各在画面哪里）、空间内可用器物清单。
- 三张词表：允许词（目标形制名）、禁用词（直接不出现在 prompt 里，见〖否定卡〗）、易合体对（见〖器物卡〗）。
- 服装状态机：角色在该场合合理的穿着与发式（朝服/常服/寝衣不混用），及跨单元穿着进度声明（"本单元起发髻已散、凤冠已除"）。与角色参考图冲突时，先决定改文字还是换参考图，别指望文字压过视觉先验。
- 声源清单：该空间恒定在响的东西（见〖声音卡〗，静默镜逐镜点名）。
- 光源与反射纪律：声明火焰只允许出现在哪几件器物上；反射面只写受光与高光（见〖器物卡〗）。

一段可直接抄进【全局设定】的模板（Good Case 版）：

```text
【全局设定】
• 画质：[如 高端真人古装宫廷生活电影质感，超高清真实细节，24fps 电影观感，180°快门自然运动模糊]
• 画面纯净度：[全片画幅保持干净，画面上缘、中部与下缘均为连续场景延伸]
• 音频：[如 仅环境音、现场音效与角色对白，无配乐]
• 其他：[跨镜头一致性声明 + 物理真实 + 表演级别，例：角色五官、服装、发型、道具、光照跨镜头严格一致；重力、惯性、碰撞符合真实物理；表演为专业影视演员级，情绪克制内敛]
• 基调：[一句到两句定住本单元情绪与风格边界——把原来要拆成道具/声音/空间/服化"纪律"的内容，合成一句自然的目标状态；例：延续上一段的安静内室氛围，灯光柔和克制，情绪保持稍微放松；场景全程停留在本间寝殿；全片对白仅为用户给定台词]
```

这段模板自身必须先过〖否定卡〗：基调里绝不出现被排除物的名词（火焰、火苗、灯芯、玻璃、静音）——出现＝喂给模型。火只写在"灯/烛台在哪亮"这类句子；声音只写"有哪些连续声源"、不写"不出现静音"；道具靠【场景与空间说明】里的陈设清单自然带出，不单开"道具纪律"行。

现代/产品向同理：档案不是古装专属。产品片要钉死"台面只有 X/Y、无杂物反光、logo 在正面朝镜头"；现代戏要声明"手机为黑色直板、无品牌 logo 露出"等，同样是先占空隙再写镜。

约束：逐镜写作不得引入档案里没有的新器物、新声源、新饰物；需要新增先回档案补一行再写镜，否则单元之间各自发明、拼接必然穿帮。

## 空间锚定与镜头写法

在所有镜头描述前，写一段【场景与空间说明】锁死站位：画左/画右/前景/背景、身体朝向、视线可达性、间距遮挡。

双人对话或对峙场景还要显式建立 180° 轴线：说明轴线由哪两人构成、机位始终位于轴线哪一侧，并固定角色的屏幕侧，例如「沈墨保持画面左侧或中左，盐铁使保持画面右侧或前景右侧」。正反打可以改变景别和肩位，但不得让双方屏幕左右无因互换。镜中切换前后的结束状态与下一镜起始状态必须能在同一空间中连续成立。

形态差异（决定哪些信息要写、哪些省略）：

- T2V：外观、场景、动作、镜头、风格全靠文本，五要素各一两句，不遗漏也不堆砌。
- I2V 首帧 / 首尾帧：首帧/尾帧已由 VAE 像素级锁定构图、外观、光影、色调，prompt 只写运动与变化 + 明确运动方向，不重复静态信息。写前先产出〖首帧锁定清单〗自检冗余。多主体首帧用位置（"画面左侧的女性"）区分，别用角色名。
- 全能参考：参考图分两类，策略完全不同，写前先判断每张 @图片N 属于哪类——
  - 视觉先验（角色设计稿/四视图/场景概念图）：只告诉模型"长什么样"。【角色设定】只做 @图片N（名称） 标识映射、不写外观；【场景资产】只做功能声明、不写场景类型/光线/色调。画面内容只写动作、状态变化、情绪；仅当参考图未覆盖的变化（脏污、汗、孕肚、发髻已散）才补写。给角色再堆外观文本会和视觉先验在 cross-attention 抢权重、反而劣化。
  - 帧锚点（把上一镜的尾帧/某个关键帧截图当 reference_image 传入）：技术上走 R2V，写作层面按 I2V 减法规则处理——画面构图、人物姿态、光影色调都被这张像素级锁定了，全部省略，只写"从这个状态出发接下来发生什么"（动作/运镜/变化）。用于跨单元续接：上一段尾帧作 reference_image（Wan3.0 里 reference_* 与 first_frame/last_frame 互斥，续接段用 reference_image 承载、非 first_frame），并声明"锁定站位朝向、延续上一段光照"。
  - 混合模式：一个 prompt 里可同时有视觉先验图（角色/场景）与帧锚点图（首/尾帧），每张按自己的类型独立套对应策略。挂图 ≤4 张为佳、色温光影要统一。
- V2V 编辑/延长：说清"改什么"+"保留什么"，单次改动 ≤3 个；风格化越大越易丢面部，极端风格丢动作细节。

### 动作具象化（禁止抽象情绪词）

模型不渲染"情绪"，只渲染看得见的动作。抽象情绪词一律翻成可视觉化的身体指令——这是 Good Case 情绪戏耐看的根本，别退回写"她很悲伤""他内心挣扎"。

关键动作必须写成起点 → 连续过程 → 终点，不能只写终点姿态。例如不要只写「跪下低头」，应写「双脚落点固定 → 身体垂直屈膝下降、膝部接触地面 → 双手撑地后伏身低头并保持原位」。跨镜动作还要让上一镜终点与下一镜起点逐项一致，避免人物瞬移、跳姿或动作重复。

| 不要写 | 应该写 |
| --- | --- |
| 她很惊讶 | 身体微微后仰，右手僵在半空，眉毛上挑，嘴巴微张 |
| 他很冷漠 | 垂眼盯着手中茶盏，指尖缓慢摩挲盏沿，全程不抬头 |
| 她强忍情绪 | 喉头极缓地动了一下，眼睫垂下，肩背松了一寸 |
| 递东西 | 右手从胸前取出卡片，手臂自然伸向对方，卡面朝上 |

表演指导里同理：写"柔声、带着心疼""喘而未甘、渐转狠厉"这种能落到呼吸/眼神/嘴角的语气词，别写"情绪复杂""很激动"。

### 视角与转场模板

跨镜衔接用物理空间描述转场，不用剪辑术语（"Cut to…"模型不吃）。叙事常用：

- 正反打：过肩从 A 肩后看 B；反打从 B 肩后看 A。机位保持在人物同侧，对话才不跳。
- 景别收紧推情绪：中景→近景→特写，配合单一核心动作递进。
- Insert/POV：镜头推近至手中器物，屏幕/器物渐占满画面（主观视角），手从画侧滑入。
- 跟随→揭示：背后跟拍穿过门/走廊，推开门强光涌入揭示新场景。
- Whip Pan 甩镜：人物猛然转头→镜头极速横摇成色条→减速后已是新场景（换场景的硬切用）。
- 焦点转移：前景器物清、背景人虚，焦点缓移到人、器物虚成光斑。

### 删冗余的正确姿势（别为了"每镜完整"反堆重复）

相同的层用引用复用，只有真正变化的才重写——每个冗余 token 都在稀释核心信号：

- 光影 / 声音：与上一镜同环境时用「与镜N一致」，不逐字重写。
- 风格锚点：T2V 与全能参考叙事镜每镜写当前镜真正变化的焦段、光圈与渲染锚点；I2V/首尾帧已由帧锁定静态风格时，只写「延续首帧既有风格」加本镜必要的焦段或运动质感，不重复色调、构图和外观。

每个镜头用六层结构（下节格式）。一镜一动作，每镜带与当前生成形态相适配的风格锚点，结尾带背景层抑制。

## 输出格式（严格执行）

纯文本，禁用一切 Markdown 语法（#、、|、-、``` 等）。一级标题用【】，二级用〖〗，列表用 •。输出正文只放模型可解析的条件信号，不夹带优化说明（说明写在正文之外）。整篇读起来像导演分镜笔记，不像合规检查清单——写"是什么、什么感觉"，不写"禁止什么、必须遵守什么"。

完整结构（Good Case 版）：

正文直接从【全局设定】起。生成模式（T2V/首帧/首尾帧/R2V/编辑）、比例、时长、分辨率都是提交时的 CLI 参数，不写进 prompt 正文。

```text
【全局设定】
• 画质：[高端真人XX电影质感，超高清真实细节，24fps 电影观感，180°快门自然运动模糊]
• 画面纯净度：[全片画幅保持干净，画面上缘、中部与下缘均为连续场景延伸]
• 音频：[仅环境音、现场音效与角色对白，无配乐]
• 其他：[跨镜一致性 + 物理真实 + 表演级别，一句合成]
• 基调：[一句到两句定住本单元情绪与风格边界，使用正向目标状态，如"延续上一段XX氛围；灯光保持XX；情绪维持XX；场景全程停留在XX；全片对白仅为用户给定台词"]

【角色设定】
• @图片N（角色名）    ← 全能参考只做标识映射；T2V 场景改写完整外观（发型/服装/年龄感/气质）

【场景资产】
• @图片N（场景名）：本场景的环境锚点，约束光影/构图/色调

【场景与空间说明】
场景：[参照 @图片N（场景名），时段+关键陈设+光源；不重复场景外观，只补时间/天气]
承接上一段：[多单元续接才写；一句交代前情站位与状态]
角色空间关系：
• @图片N（角色名）[位置/身体朝向/视线/关键姿态]
• @图片N（角色名）[...]
• 背景层：[帷幔/窗外/环境]，保持低存在感

每个镜头
【镜N】景别+运镜(含相对量级)+视角（起始s-结束s）

画面内容：[主体动作+姿态+表情+视线，50-80字，结尾带"背景虚化，保持低存在感"，不重复运镜参数]
光影：[主光源方向+氛围词，1-2句，≤40字]
声音设计：[环境音+动作音效，≤40字；无台词镜按〖声音卡〗点名 1-2 个真实声源]
台词：[@图片N（角色名）]（表演指导）：台词内容。无台词直接写"无"两个字（不写"全片本镜无台词，人物嘴唇闭合"这类防御句）
风格锚点：[每镜都完整写一遍，含具体焦段+光圈，如 "85mm f/2.0 浅景深，低饱和暖木与玉白，柔和烛光"；不要用"同镜1"省略]
衔接：[下一镜初始状态，1句]
```

最后一镜的"衔接"改写成"结束状态：..."，明确交代全片收在什么姿态/站位/道具状态，方便下一单元续接或观众收势。

全部镜头结束后另起一段收束全局：一句到两句话复述一致性约束与本单元情绪边界，例：「全片保持角色、服装、道具、光照跨镜头一致；人物表演克制，动作幅度小；运镜平稳舒缓。」

六层合计 ≤200 字/镜。运镜量级用"缓慢/快速""小幅/大幅""贴地/俯视"等相对词，不写绝对数值（时间标注除外）。有台词的角色用 @图片N（名） 指代。

### 类型适配

叙事：正打/反打 + 景别收紧推情绪 + 台词带表演指导。广告：产品镜稍强光、末镜直视镜头破第四面墙。搞笑：笑点前"环境音骤降半秒"留白 + 动作幅度放大。教程：固定镜头为主、主体居中、手部动作详写。

## 调度优先于合规（评审以出片为准）

三张卡（否定/声音/器物）和自检清单都是降低概率风险的工具，不是判通过/不通过的红线。一条"逐条合规"的 prompt 可能平淡，一条"踩了某条提示"的 prompt 可能出片更好——最终只有一个裁判：跑出来的片。写和评审时，先想调度，再对着卡做取舍。

情绪戏真正耐看靠的是导演级的调度（staging），不是器物措辞合规。可泛化的几条：

- 把机位给被骂的人，怒吼走画外音：暴怒/迁怒戏里，镜头落在听者脸上的反应（捂脸、含泪、肩膀发抖），施暴者的咆哮作为画外音压入——比正面拍施暴者张口更揪心，也顺带规避口型压力。台词栏标「画外音」并声明说话者不在画内配口型。
- 情绪顶点敢怼特写：整段最狠的一句/最崩的一刻，用 85mm 微仰视近景把脸怼满画面（焦段随景别走，这镜的风格锚点就要写长焦）。别为"每镜均衡"把高潮摊成中景。
- 开场建立镜交代环境后果：暴怒砸物之后，可用一个稍宽的建立镜把"上一段已砸乱的现场"（碎瓷、歪斜家具、水渍）收进画面，用空间后果承接情绪，而非只拍人物。
- 跨镜用因果型身体细节衔接：上一镜扇耳光→下一镜"肿起的脸颊"；上一镜泼水→下一镜"地面水渍漫过碎瓷"。让物理痕迹在两镜间continuity，比写"保持上一镜姿态"更可信。
- 节拍后移是 Wan3.0 固有属性：暴力动作（耳光、砸物）实测比标注时间到得晚，别因为"7s 该甩巴掌没甩"就判崩——看整段节奏是否连贯，而非逐镜对表。

评审 meta 规则：不要因为某条 prompt 命中了某张卡的"高危条件"就断言它必崩、要求返工；先出片、看片。反过来，也不要把"每个动作精确落在第几秒"当质量指标——那是模型自决的相对节拍。合规服务于出片，不是出片服务于合规。

重试归因规则：首次失败先检查素材、提示词矛盾、时间预算和空间/动作缺口；修正后仍只在不同抽卡间随机出现的发音、口型、镜序或动作偏差，归为 generation/model 执行波动。连续 2–3 次同类失败时停止继续堆同义约束，向用户说明命中率边界，并在"保持完整 prompt 继续抽卡 / 经授权改变生成方案"之间选择，不得静默换方案。

## 出片前自检清单（主纲）

- [ ] 形态已确定（T2V/首帧/首尾帧/R2V 全能参考/编辑）——作为提交时的 CLI 参数，不写进 prompt 正文；正文从【全局设定】起
- [ ] 〖设定档案〗已建（内部准备文档，不直接抄进 prompt）：世界清单、光源清单、声源清单、服化状态；对年代/奇幻/产品类必做
- [ ] 【全局设定】五行齐（画质/画面纯净度/音频/其他/基调），画面纯净度只写一句正向目标状态，基调一句自然合成，不出现"道具纪律/声音纪律/空间纪律/服化纪律"这类分立的合规语
- [ ] 调度先想过：情绪戏是否用了对的机位（被骂者的反应特写 / 怒吼走画外音 / 顶点敢怼 85mm 特写 / 建立镜交代后果 / 因果型身体细节衔接），而非只顾措辞合规
- [ ] 〖否定卡〗扫描：全文无"不要X"式否定句；被排除物的名词（现代器物词、火焰/静音等）根本不出现在 prompt 里，靠场景陈设与自然描述占位
- [ ] 〖器物卡〗（风险提示）：反射只写高光不写被反射物；容器×火源/镜面×人影已分句；多原型条件叠满时优先改素材/形制，但这是概率风险，不据此单独判 prompt 必崩
- [ ] 〖声音卡〗（风险提示）：静默镜逐镜点了声源；无台词镜用"台词：无"两字，不写"人物嘴唇闭合"这类防御句；"死寂/极低底噪"是别去赌的提示，非必然静音
- [ ] 复用与重写分清：光影/声音与上一镜同环境时可引用上一镜；T2V/全能参考按本镜变化写焦段与渲染锚点，I2V/首尾帧只引用首帧既有风格并补必要运动参数
- [ ] 抽象情绪词已翻成动作：全文无"很悲伤/情绪复杂/很激动"这类词，落到呼吸/眼神/嘴角/肢体的可视觉化指令
- [ ] 关键动作三段齐：起点、连续过程、终点均已写明；跨镜终点与下一镜起点一致
- [ ] 对话轴线已锁定：180°轴线、机位同侧及角色画左/画右关系明确，正反打不无因换侧
- [ ] 最后一镜的"衔接"改为"结束状态：..."，且全部镜头结束后另起一段全局一致性收束语
- [ ] 素材互斥检查：first_frame/last_frame 与 reference_* 未混用；last_frame 配了 first_frame
- [ ] 全能参考：角色只做 @图片N（名） 标识映射，无外观堆砌；挂图克制（≤4 张为佳）、风格统一
- [ ] I2V/首尾帧：prompt 只写运动+变化+明确方向，未复述静态信息
- [ ] 无绝对数值运镜：用相对量级词；时间戳和台词截止均按软约束处理，不承诺绝对秒点
- [ ] duration 与对白窗口均已核算：先用 需求时长 = ⌈台词字数 ÷ 4⌉ + 计划静默 规划总时长，再逐句计算字数÷发声窗口，并核对全局目标字速；10–30s 默认单条生成，短镜按动作复杂度判断，不把每镜≥3s当硬门槛
- [ ] 专有词已核对：真实出现次数正确；全局与逐处均用字源/拼音/声调注记；未把发音命中率写成保证
- [ ] 台词逐字保留：超长靠加时长/跨镜/软截止声明解决，未擅改
- [ ] 重跑方案未越权：用户要求优化提示词重跑时，保持完整 prompt 单条原生生成；分段、后期加速或独立配音已获得明确授权
